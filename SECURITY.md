# Security Policy

## Reporting a Security Issue

This is a curated knowledge repository. Direct security vulnerabilities in the repo code itself are minimal, but we take the following seriously:

### What to Report

- **Malicious links** — a listed resource has been compromised or redirects to malware
- **Phishing resources** — a listed resource has changed ownership and now acts maliciously
- **Dependency vulnerabilities** — in our link-checker or automation scripts
- **Supply chain issues** — in any tooling this repo depends on

### How to Report

**Do NOT open a public GitHub issue for security concerns.**

Email: **security@awesome-research-hub.dev**

Include:
- Description of the issue
- The affected URL or file
- Steps to reproduce or verify
- Your suggested remediation (optional)

We will respond within **48 hours** and remediate within **7 days** for confirmed issues.

### Scope

| In Scope | Out of Scope |
|----------|-------------|
| Malicious/compromised links in the resource list | Content of third-party sites we link to |
| Vulnerabilities in repo automation scripts | Security of linked projects themselves |
| Credential exposure in commits | General security questions |

### Safe Harbor

We consider responsible disclosure research conducted under this policy to be authorized. We will not pursue legal action against researchers who follow these guidelines.
